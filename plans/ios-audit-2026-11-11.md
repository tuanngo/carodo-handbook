## Conventions every step must honour (from `carodo-ios/AGENTS.md`)

- Swift 6, approachable concurrency: the app target defaults to the main actor. Write **no
  `@MainActor`** on views, view models or services; mark `nonisolated` what must run off it; move
  work off it with `@concurrent`, never `Task.detached` or GCD.
- `let` by default; no `!`, `try!`, `as!`; `try?` only where failure is ignorable and the fallback
  never reads as a fact.
- Every user-facing string lives in a String Catalog under `Carodo/Resources/Localization/`
  (one table per feature plus `Common`), with a translator comment, English and Vietnamese; views use
  the generated symbols (`Text(.Drive.statusLive)`), never `Text("literal")`. `LocalizationTests`
  fails otherwise. A Vietnamese line is native copy for the same intent, never word for word.
- Reuse before adding: search for an existing type or helper before writing one.
- P5: no coordinate, place name or plate in logs or test fixtures. Test coordinates are synthetic
  (the tests use `latitude: 10 + …, longitude: 106.7`, or `45 / 10`).
- A changed threshold or state transition has unit tests on both sides and an updated
  `docs/tracking.md`. A behaviour change updates the matching `docs/specs/*.md` in the same commit.
- Done means: `task format`, then `task lint`, `task warnings` and `task test` pass; tests added;
  the exact commands and results in the report; device checks still needed listed.

       /// Shows `content` in `view`, sized `size` (nil: the content's own size within `fitting`).

## Step 4 (F1): Replay's map takes a finger the way the Map tab does

### Why

On 2026-11-10 the Map tab's follow camera was fixed so a finger landing on the map stops the camera
at once and only a drag of the map's centre ends the follow (commit `161de4d`): a
`MapTouchRecognizer` hears the touch beside MapKit's gestures, and `regionWillChangeAnimated` asks
MapKit's recognizers only while a finger is held, because that question walks every gesture
recognizer under the map and a camera set per frame fires the delegate per frame. Replay still uses
the older detection: while following, `ReplayMapCoordinator.show` sets `mapView.camera` every frame,
each set calls `regionWillChangeAnimated`, and that handler walks the whole gesture tree at 60 Hz.
A single tap on the map can also end Follow (a tap recognizer's `.ended` state counts as a user move).

## Step 5 (F4): a detection fix with no speed neither counts nor resets

### Why

Auto Mode confirms a drive after four consecutive trusted moving fixes (`DrivingDetectionEngine`).
Core Location reports `speed = -1` when it has no speed (a Wi-Fi or cell position, the first fixes of
a cold start). The engine reads such a fix as `.slow` (because `-1 < 3.33`) and resets the run, so
one speed-less fix between four moving ones delays the start by a whole run, and the window's log
counts it under `slow=`. The codebase's other reader of speeds, `StopRule`, treats a fix with no
speed as saying nothing (`StopRule.swift:33`). Make detection consistent: no speed is `.untrusted`
(neither counts nor resets), as a fast fix within its noise already is.

### Current state

`Carodo/Core/Tracking/DrivingDetectionEngine.swift:49-62`:

```swift
func read(_ sample: LocationSample, now: Date) -> Reading {
    guard sample.horizontalAccuracyMeters > 0,
        sample.horizontalAccuracyMeters <= configuration.maxHorizontalAccuracyMeters
    else { return .inaccurate }
    let age = now.timeIntervalSince(sample.timestamp)
    guard age >= 0, age <= configuration.maxSampleAgeSeconds else { return .stale }
    // Device, 2026-11-03: a phone still indoors reported 3.4–3.7 m/s four times in a row, each
    // with a 2.5–2.7 m/s accuracy; counted, that would have started a drive.
    if sample.speedMetersPerSecond < configuration.minimumSpeedMetersPerSecond { return .slow }
    guard let trusted = sample.trustedSpeed(factor: configuration.speedTrustFactor),
        trusted >= configuration.minimumSpeedMetersPerSecond
    else { return .untrusted }
    return .moving
}
```

`Reading.untrusted` is documented at `:43-44` as "Fast, but within its noise: neither counts nor
resets." `DetectionWindowStats.add` (`DetectionWindowStats.swift:52-74`) counts `.untrusted` under
`untrusted` and `usable`, and reads `maxSpeedMps` only when `speedMetersPerSecond >= 0`, so no change
is needed there. `docs/tracking.md:305-306` describe the rule.

### Do

1. Before the `.slow` line add:
   ```swift
   // No speed at all (a Wi-Fi or cell position, a cold start): evidence of nothing, as `StopRule`
   // reads it. It never resets a run of moving fixes.
   if sample.speedMetersPerSecond < 0 { return .untrusted }
   ```
   Update the `Reading.untrusted` doc comment: "Fast but within its noise, or with no speed at all:
   neither counts nor resets."
2. Tests in `CarodoTests/DrivingDetectionEngineTests.swift` (same style as its existing tests,
   synthetic coordinates): (a) three moving fixes, one with `speedMetersPerSecond: -1` and good
   accuracy, then one moving fix → confirmed on the fourth moving fix (count survives); (b) a fix
   with `speed: -1` alone never confirms, and `read` returns `.untrusted`; (c) a slow fix
   (`speed: 1`) still resets (both sides of the rule).
3. `docs/tracking.md`, the `requiredMovingSamples` row (`:305`): change "one slow sample resets the

   (2026-11-11: `StopRule` reads it the same way)". No threshold value changes.

### Verdicts after the first device capture (2026-11-11, iPhone 14, Debug build, charging)

Numbers in `carodo-ios/docs/operations/device-testing.md` (Results, 2026-11-11).

- **P1 launch: not now.** About 453 ms to foreground-active, of which 366 ms is the first frame's
  rendering; samples inside `startServices` span about 65 ms. The services are not what the
  person waits for, so moving them after the first frame would save little. Re-measure once on a
  Release build, a cold launch, three runs, before touching it.
- **P4 onboarding idle: not worth doing.** 1.13 % CPU averaged over 30 s on Welcome; the wheel's
  tick took 19 ms of samples in that window. Stopping the display link would save a fraction of a
  percent. PV-14 stays open only for its unplugged battery reading and Skip/Back interaction.
- **P2, P3, P5: not measured.** P2 and P5 are small, testable changes with no UI; take them up
  with the next slice that touches `DependencyContainer` or the Passport. P3 is TD-12.
